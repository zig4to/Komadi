# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

@AGENTS.md

## Commands

- `npm run dev` — dev server on **https://localhost:3000** (HTTPS, not HTTP — required because the backup feature uses the File System Access API / Web Share API, which need a secure context). Uses a self-signed cert auto-generated into `certificates/` on first run.
- `npm run build` — production build; static export to `out/` (`output: "export"` in `next.config.ts`).
- `npm run lint` — ESLint (flat config, `eslint.config.mjs`).
- `npm run backup` — exports the `songs` table to `backups/songs-<timestamp>.json` via the Supabase REST API (`scripts/backup-songs.mjs`).
- No test suite exists in this repo.

Supabase Edge Functions are deployed separately from the Next.js build, via the Supabase CLI, not `npm run build`:

```powershell
supabase functions deploy guess-era
supabase functions deploy similar-songs
```

Both read one shared secret (`supabase secrets set ANTHROPIC_API_KEY=sk-ant-...`). Full one-time setup (CLI install/login/link, secret, deploy, smoke test) is documented step-by-step in README.md under "AI predlog obdobja".

## Architecture

**Fully static, client-only app — no custom server.** `next.config.ts` sets `output: "export"` (deployed to GitHub Pages by `.github/workflows/deploy.yml`, `basePath` driven by the `REPO_NAME` constant at the top of that file). The whole app is one client-component tree from `src/app/page.tsx` → `Dashboard.tsx`. There are no Next.js API routes; the only server-side code is the two Supabase Edge Functions under `supabase/functions/`, which are their own deploy target.

**All state lives in `Dashboard.tsx`.** It owns `songs`, `filters`, `activeView` (`"list" | "newest" | "popular"`), and all form/modal state, passed down as props to `SongCard`, `SongForm`, `Filters`, `SettingsMenu`. There is no global store (no Context/Redux/Zustand) — everything is prop-drilled from this one component.

**AI calls always go through a Supabase Edge Function, never straight from the browser to Anthropic.** `guess-era` (suggest a decade from title+author) and `similar-songs` (find similar songs via Claude + web search) are invoked with `supabase.functions.invoke(name, { body })` and read `ANTHROPIC_API_KEY` from `Deno.env` server-side. This is what keeps the key out of the client bundle — necessary because the app is a static export with no backend to otherwise hide it behind. Both functions share the same secret.

**Cross-component UI state (open/closed panels, theme) syncs via localStorage + a custom `window` event, not lifted React state.** See `usePersistentBool` in `src/lib/usePersistentBool.ts` and `useTheme` in `src/lib/useTheme.ts`: each reads/writes one `localStorage` key and dispatches/listens for a custom event (`komadi-storage`, `komadi-theme`) so independent component instances (or a single component across a page refresh) stay in sync without sharing a parent. `Filters.tsx` exports two separate components, `FiltersToggle` (the pill button, rendered inline with the "Novo"/"Popularno" buttons in `Dashboard.tsx`) and `Filters` (the panel, rendered separately below) that share state this way, and `Dashboard.tsx`'s `jamOpen` uses the same hook so refreshing the page mid-jam-session doesn't bounce back to the home screen. The `Filters` panel only closes via the `Filtri` toggle button or its own "Počisti filtre" button (always visible at the top of the panel, not gated on `hasActiveFilters`) — there is deliberately no click-outside-closes handler, so opening it and clicking elsewhere on the page (e.g. a genre chip inside it) doesn't unexpectedly dismiss it.

**Data model:** the core table is `songs` (`supabase/schema.sql` + `supabase/migrations/`, applied by hand in the Supabase SQL Editor — there's no migration runner). `genre` and `era` are fixed enums (`GENRES`, `ERAS` in `src/lib/constants.ts`, typed as unions in `src/types/song.ts`); `mood` and `origin` are free-text and user-extensible — `DEFAULT_MOODS`/`DEFAULT_ORIGINS` are only seed suggestion lists, not constraints, and `SongForm` lets the user type a new value that then shows up in future pickers/filters. `copy_count` drives the "Popularno" sort (see below). Up to three chord sources per song: `chords_url` (own-hosted PDF), `chords_source_url` (Ultimate Guitar link), and `zabrenkaj_url` (link to the song's page on zabrenkaj.si, a Slovenian chords site — `0016_add_zabrenkaj_url.sql`; only the link is stored, never the page content). `zabrenkaj_url` was bulk-filled once for the ~94 library songs that exist there, by matching titles against `https://www.zabrenkaj.si/vse-pesmi/` and confirming the artist from each candidate page's `<title>` (`Izvajalec - Naslov - Akordi …`); new songs get it via the `dodaj-iz-cakalne-vrste` skill (step 4b) or by hand in `SongForm`. A second table, `author_images` (`author` text PK, `image_url`), holds one optional photo per author, settable from the small camera-icon button on any `SongCard` (`onSetAuthorImage`) and read into `authorImages` state in `Dashboard.tsx` for use as background art on cards/highlights. `queued_songs` (`title`, `author` only), `import_batches` (one row per run of the `dodaj-iz-cakalne-vrste` skill, `report` jsonb shaped like `ImportReport` in `src/types/song.ts`; songs point to it via `songs.import_batch_id`, `0021_add_import_batches.sql` — shown on the "Čakalna vrsta" page in the "Poročila" and "Zgodovina dodajanja" tabs, `src/components/ImportTabs.tsx`), `song_reports` (`song_id` FK with `on delete cascade`, a `title`/`author` snapshot, optional `note` — written by "Prijavi napako" in the `SongCard` hamburger menu, which opens a small inline form at the bottom of the card; `0018_add_song_reports.sql`. `Dashboard.tsx` owns the `reports` state; while a song has any open report it is hidden from the "Vsi Komadi" list only (`reportedSongIds`, filtered in `displaySongs`) and shown instead on the full-page "Popravi skladbe" view (`fixOpen`, a `usePersistentBool` alongside `jamOpen`/`goalOpen`, mutually exclusive with them): each song as a `SongCard` plus its report notes, a pencil button right of each note to edit it inline (needs the update policy from `0019_song_reports_update.sql`), "Uredi" (inline `SongForm`) and "✓ Popravljeno" (deletes all of its reports, which returns it to the list). `SettingsMenu.tsx` keeps a read-only quick-overview dropdown of the same reports (tap to expand the note; no ✓ there — resolving is only on the full page), passed in as props, plus a button that opens the full page) and `goal_extras`/`jam_extras` (see below) round out the schema. RLS policies allow public read/write with just the anon key — there is no auth, by design (personal single-user app; see "Varnostna opomba" in README.md before changing this).

**Trap: "Pred 1960" and "1960s" render as the same home-screen label.** `formatEraLabel` in `src/components/HomeHighlights.tsx` maps both era values to "60's" (it strips the "19" prefix from any `<NN>s` value, and special-cases "Pred 1960" to the same string). Since the "Obdobja" row on the home screen only shows one card per era that actually has ≥1 song, assigning a `<1960` song to whichever of the two values doesn't already have songs creates a second, visually-identical "60's" card. Before assigning either value, check which one is already in use (`select=id&era=eq.<value>`, both are plain strings, no DB-level enum) and use that one — this already happened once during the CCR import and was fixed by moving songs to the active value.

**Trap: React portals break the "click outside Novo/Popularno closes the view" listener unless marked.** `Dashboard.tsx` has a `document`-level `pointerdown` listener (active only when `activeView !== "list"`) that resets `activeView` to `"list"` on any click outside `[data-view-toggle]`/`[data-view-section]` — but content rendered via `createPortal` (the merged `ChordsButtons` dropdown, its `PdfViewer` overlay, `SongCard`'s action-menu dropdown) is appended to `document.body`, physically outside `[data-view-section]`, even though it's logically part of it. Without an exception, clicking e.g. "Ultimate Guitar" (formerly "UG Tabs") inside that dropdown while on the Popularno tab got treated as an outside click and silently bounced the view back to "Vsi Komadi" before the link even opened. Fix/pattern: any portaled element that should count as "inside" the current view carries `data-view-portal`, and the listener's exclusion check includes `target.closest("[data-view-portal]")` alongside the other two. Any new `createPortal` content reachable from inside a Novo/Popularno/list row must carry this attribute too, or it will silently re-trigger this bug.

**"Popularno" popularity is driven by chord-button clicks, not song-title clicks.** Earlier versions copied the title to the clipboard on any click anywhere on a card and counted *that* towards `copy_count` — this was removed. Now `copy_count` only increments when the "Ultimate Guitar", "Zabrenkaj.si" or "PDF akordi" button is clicked (`handleChordsClick` in `Dashboard.tsx`, threaded down as `onChordsClick` through `SongCard`, `ChordsButtons`, and `FeaturedArtists`/`SongRow`). Cards no longer copy anything to the clipboard at all.

**"Vsi Komadi"'s header button swaps meaning depending on whether a filter is active.** With no active filter it's "Skrij komade"/"Prikaži vse komade" (`songsVisible`, defaulting to collapsed on desktop via a one-time mount effect — see the ESLint gotcha below for why that effect is a known, intentional lint exception). The moment any filter is active (`hasActiveFilters(filters)` or `authorFilter`), the same slot renders "← Nazaj" instead, which calls `handleBackFromFilter` (clears filters, closes the `Filters` panel, restores scroll position) — the two buttons never show at once.

**"Naključno"/"Delno naključno" share one `randomPick` slot, with a flag for how it was picked.** `pickRandom()` (plain "Naključno") and `handlePartialConfirm()` (after picking a dimension+value in "Delno naključno") both set the same `randomPick` state, but only the latter sets `randomPickFromPartial = true`. This matters for the "↻ Izberi drugo" button: `handlePickAnother()` branches on that flag — for a plain pick it just calls `pickRandom()` again, but for a partial pick it clears `randomPick` and re-opens the "Delno naključno" selection form (`handlePartialStart()`, which also re-rolls which dimension — genre/author/era/mood/origin — is asked for) rather than silently picking a new song from the whole library. The "↻ 5" button (`pickRandomFive`) is independent of this flag — it always samples from the currently filtered pool and renders a `SongCard` grid underneath, closed by `setRandomFive(null)` whenever a new pick/partial-pick happens. Author matching in "Delno naključno" is soft (`s.author.toLowerCase().includes(word)` per word in the query, any order) rather than an exact match, so a partial or reordered name still finds the artist.

**"Jam" is a live, shared queue for a band practice session, synced via Supabase Realtime.** Two columns on `songs` (`jam_added_at`, `jam_played`) turn any existing song into a queue entry — `jam_added_at` doubles as the queue order and "is currently in the jam" flag; a separate table, `jam_extras` (title/author/played only, no genre/era/etc.), covers songs suggested during a jam that aren't in the library yet ("Skladbe ni" quick-add). `Dashboard.tsx` merges both into one `jamItems` list (see the `JamItem` discriminated union) and always shows a "Trenutna skladba"/"Naslednja skladba" label on the first two unplayed entries. Because a jam session has multiple people adding/checking off songs from their own phones at once, `Dashboard.tsx` subscribes to Supabase Realtime (`supabase.channel("songs-and-extras").on("postgres_changes", ...)`) for `songs`, `jam_extras`, and `goal_extras` (see below) and merges every INSERT/UPDATE/DELETE straight into local state — this requires the tables to be added to the `supabase_realtime` publication (`supabase/migrations/0013_enable_realtime.sql`, `0015_add_goal_list.sql`), which is *not* covered by RLS policies and must be run once by hand like every other migration in this repo. There is no origin-filtering/de-duplication of a client's own optimistic update against its own echoed realtime event — the echo just re-applies the same value, which is harmless.

**"Mojih 20 skladb" is a second, independent queue — same pattern as Jam, different purpose (a personal songs-to-learn checklist, not a live session).** Own columns (`goal_added_at`, `goal_learned`) and own extras table (`goal_extras`), opened from the ⋮ menu (`SettingsMenu`'s `onOpenGoal` callback) rather than a header pill button, with its own header swap (amber target icon + "Mojih 20 skladb" instead of Jam's fuchsia lightning bolt + "Bitne Jam!"). Opening one closes the other (`jamOpen`/`goalOpen` are both `usePersistentBool`-backed, and each toggle explicitly sets the other to `false`). Deliberately does **not** show the "Trenutna/Naslednja skladba" labels — those only make sense for a live session's play order, not a static checklist.

**The main "+" ("Dodaj skladbo") button offers a quick, low-friction path alongside the full form.** Clicking it opens a choice (`addChoiceOpen`) between "Hitro" (title + author only, written to `queued_songs` — for bandmates to jot down a song suggestion without filling in genre/era/etc.) and "Prek telefona" (the existing full `SongForm`, unchanged). Queued entries live in `queuedSongs` state in `Dashboard.tsx` (loaded on mount, refreshed whenever the ⋮ menu opens via `onRefreshLists`). `SettingsMenu.tsx` shows a quick "Čakalna vrsta" overview (✕ delete, plus a button to open the full page); the full-page view (`queueOpen`, `usePersistentBool`, mutually exclusive with Jam/Goal/Popravi skladbe, Android-Back-aware) shows each entry in a card with "Dodaj v knjižnico" (inline prefilled `SongForm`; on a successful insert the queue entry is deleted via `queueAddingId`), "Spletno iskanje" and a confirmed remove. The `.claude/skills/dodaj-iz-cakalne-vrste/` skill automates turning a queued title+author into a fully-populated song (UG chords link, zabrenkaj.si link if the song exists there, genre/era/origin/mood research, PDF, author image) and is the intended way to process this queue — see that file for the exact steps (including the mood-research approach and the "Pred 1960"/"1960s" trap above).

**Component map:**
- `SongCard.tsx` — one song: the author photo is a clipped background image — portrait (taller-than-wide) photos are cropped from `PORTRAIT_FOCUS_Y` (20%, `src/lib/constants.ts`) instead of the center so the head stays visible, detected on `onLoad` (the "Avtorji" home tiles in `HomeHighlights.tsx` do the same via their preload); clickable author name (sets the search filter to that author), a violet "+" that adds the song to Jam (`onAddToJam`, flips to a green checkmark for 1.4s as click feedback — otherwise the button gives no indication anything happened), a merged "Akordi" `ChordsButtons` at the bottom of the card, and a single hamburger button (top-right) that opens a portal dropdown menu (Uredi/Dodaj v Jam/Izbriši/Prijavi napako) instead of three separate icon buttons — same portal+positioning pattern as `ChordsButtons`' merged mode, and its own dropdown div also carries `data-view-portal` (see the Novo/Popularno gotcha below). "Podobno" (AI similar-songs panel) is currently commented out (not deleted) in this file — state, handlers, button, and results panel are all present but inert; re-enabling it is a matter of un-commenting, not rebuilding.
- `ChordsButtons.tsx` — the shared chord-link UI, reused on `SongCard.tsx` and the compact card/row components that don't have room for full labels: `CompactCard`/`CompactRow` (Novo/Popularno tabs), `RecentGroupSongRow` (Novo-po-… groups), and `SongRow` in `FeaturedArtists.tsx` (Predstavljeno). Three render modes via props: plain (separate "UG"/"Zabrenkaj.si"/"PDF" pills), `stacked` (lay them out vertically instead of in a row), and `merged` (single "Akordi" button that opens a small portal dropdown — used almost everywhere now). Dropdown order is fixed: "Ultimate Guitar" (orange stylized-"G" line icon — deliberately not UG's real logo), "Zabrenkaj.si" (green guitar icon, the same `GuitarIcon` as the "Bitne Tabs" header), "PDF akordi" (red document icon) last; each row renders only if its source exists. Below a divider, every song additionally gets "Spletno iskanje" (sky globe icon): a Google search for `avtor naslov Akordi` (origin `Slovenska`/`Yugo`) or `avtor naslov Chords` (anything else, incl. null origin), opened with `target="_blank"` — Google forbids `<iframe>` embedding, so in the installed Android PWA it opens as a Custom Tab over the app rather than a true in-app overlay. It does **not** count towards `copy_count`. So `merged` shows the menu whenever `sourceCount >= 1`; a song with no sources gets just a plain "Spletno iskanje" pill (shortened to "Splet" next to other plain pills). The dropdown panel has an amber border matching the "Akordi" button. The dropdown's `left`/`right` position is computed from the button's `getBoundingClientRect()` on open; pass `menuAlign="right"` when the button sits near the right edge of its row (e.g. `CompactRow` on Popularno, `SongRow` in Predstavljeno) so the menu doesn't overflow off-screen — omit it (defaults to `"left"`) when the button is more central/left, like on `SongCard.tsx`. Both the dropdown and the full-screen `PdfViewer` portal carry `data-view-portal` (see gotcha below).
- `ListenButton.tsx` — green icon-only (music note) button rendered by `ChordsButtons` right of the "Akordi" button (only in `merged` mode, so everywhere "Akordi" appears). Opens the same kind of portal dropdown (`data-view-portal`, emerald border to match the green button, same `menuAlign`): "Spotify" (stored `spotify_url` from `0020_add_spotify_youtube_music_urls.sql` if set, else a Spotify search `avtor naslov`; exact-track links need a Spotify Web API Client ID/secret, kept only as non-`NEXT_PUBLIC_` vars in `.env.local` for a one-off local fill script, never in the bundle), "YouTube Music" (stored `youtube_music_url` if set, else a `music.youtube.com/search?q=avtor naslov` search — deliberately never the stored `youtube_url`, which is often a lyric video) and "YouTube" (stored `youtube_url` from `0017_add_youtube_url.sql` if set, else a YouTube search `avtor naslov` + ` lyrics` for non-Slovenska/Yugo songs). `youtube_url` was bulk-filled by a one-off local script scraping YouTube search results (`ytInitialData`), in batches of ~20 with pauses because YouTube rate-limits after ~20 quick requests: foreign songs prefer a lyric video (for singing along), domestic ones the official video/audio; only confident matches were written. The `dodaj-iz-cakalne-vrste` skill (step 4c) now looks up all three listen links for new songs — `youtube_url`, `youtube_music_url` (the album-version `<Artist> - Topic` upload, opened as `music.youtube.com/watch?v=`) and `spotify_url` (Spotify Web API, only if `SPOTIFY_CLIENT_ID`/`SPOTIFY_CLIENT_SECRET` are in `.env.local`) — writing only confident matches, else null). `youtube_url`/`spotify_url`/`youtube_music_url` are omitted from `NewSong`, so `SongForm`/import never touch it. Neither link counts towards `copy_count`.
- `SongForm.tsx` — add/edit modal; the AI era-guess button lives here, plus the "Akordi (PDF)" upload (goes straight to the `song-chords` Supabase storage bucket, public URL written back to `chords_url`), and plain URL fields for "Ultimate Guitar (povezava)" (`chords_source_url`) and "Zabrenkaj (povezava)" (`zabrenkaj_url`). Accepts either `initial` (editing an existing `Song`) or `prefill` (title/author only, used when adding a song suggested by "Podobno" — currently unreachable while that feature is commented out, see above).
- `PdfViewer.tsx` — renders a chord PDF (from `chords_url`) directly into a `<canvas>` via `pdfjs-dist`, one page at a time, instead of leaving it to the browser's built-in PDF viewer — several mobile browsers (Android especially) don't render a PDF inline in an `<iframe>`, they just download it and offer to open it in an external app. `SongCard.tsx`/`ChordsButtons.tsx` decide whether to use this (own-hosted `.pdf`) or a plain external link (e.g. an Ultimate Guitar URL) based on whether `chords_url` ends in `.pdf`. Also owns a floating autoscroll control (bottom-right, speed 1–13, play/pause) — the scroll loop tracks its own sub-pixel "precise" scroll position in a ref instead of reading `element.scrollTop` back each frame, because the browser rounds `scrollTop` to whole pixels and at low speeds the fractional per-frame increment would otherwise never register and the scroll would stall. The control's on-screen position/size is corrected against `window.visualViewport` (not just CSS `position: fixed`) so it stays pinned to the real bottom-right corner and a constant on-screen size through mobile pinch-zoom.
- `Filters.tsx` — `FiltersToggle` + `Filters`, see above.
- `SettingsMenu.tsx` — theme switch, backup (download/share via `src/lib/backup.ts`), song import (via `src/lib/importSongs.ts`), the "Čakalna vrsta" list (view/delete `queued_songs` entries), the "Popravi skladbe" quick overview (`song_reports` from `Dashboard.tsx` props, with a link to the full page), and the "Mojih 20 skladb" menu item (calls `onOpenGoal` up to `Dashboard.tsx`), all behind one dropdown.
- `src/lib/importSongs.ts` — parses the two supported bulk-import formats (custom `.txt`, and `.json`) into `NewSong[]`; format spec is in README.md "Uvoz skladb". Bulk import never sets `chords_url`/`chords_source_url`/`zabrenkaj_url`/`image_url` — those are always added afterwards, per song, through the UI (or directly against Supabase).

**Android hardware Back closes the current in-app view instead of exiting the PWA.** The manifest runs `"display": "standalone"`, and the app is a single client-rendered page with no router — it never pushed browser history entries, so on Android the system Back gesture used to close the installed PWA outright rather than backing out of whatever filter/modal/panel was open. `src/lib/backNavigation.ts` (a module-level LIFO stack + one shared `popstate` listener) and `src/lib/useBackableOpen.ts` (the hook components call) fix this: any component with an existing `isOpen` boolean and an existing close function — the era/genre/author filter view, the Novo/Popularno tabs, the add/edit `SongForm`, `PdfViewer`, the `Filters` panel, `SettingsMenu` — calls `useBackableOpen(isOpen, onClose)` once, and Back then closes just the most-recently-opened one, in order, exactly as if its own close button/outside-click had been used. It never duplicates the existing close logic, only calls it. Closing one view and opening another in the same render (e.g. a ⋮ menu item that closes the menu and opens "Popravi skladbe"/"Mojih 20 skladb") used to race the async `history.back()` against the new `pushState` and make Back exit the PWA; `backNavigation.ts` now defers pushes (`pendingPushes`) until its own pending backs have fired. Every new full-page view must call `useBackableOpen` so Back returns to the home screen. Known limitation: closing a non-full-screen panel out of LIFO order (via its own button while something opened *after* it is still open) can desync the stack by one entry — self-corrects after one extra Back press; not reachable for `PdfViewer` since it's always full-screen and therefore always topmost.

## Windows/Turbopack dev quirks

- Tailwind v4's important modifier is a **trailing** `!` (`mt-3!`) — a leading `!mt-3` (the v3 syntax) is silently ignored, not an error.
- The dev server sometimes doesn't pick up new Tailwind arbitrary-value/important classes via HMR. If a style change doesn't appear, kill the dev server and re-run `npm run dev` before assuming the class is wrong.
- Turbopack's CSS worker has been observed to crash on Windows (exit code `0xc0000142`) after repeated hot-reloads. If `next dev` starts returning 500s on every request, stop it, `rm -rf .next`, and restart.
- After `git pull` adds a new dependency to `package.json`, `node_modules` doesn't update itself — `npm run dev` will start fine but the feature using that dependency fails at runtime (e.g. `PdfViewer.tsx` throwing "Cannot find module 'pdfjs-dist'" the first time it renders). Run `npm install` after any pull that touches `package.json`/`package-lock.json`, then restart the dev server.

## ESLint react-hooks gotchas

`eslint-plugin-react-hooks` here enforces two rules that are easy to trip
when writing a new custom hook:
- **No ref writes during render** (`react-hooks/refs`) — `someRef.current = x` must happen inside a `useEffect`, never directly in the component/hook body. See `src/lib/useBackableOpen.ts` for the fix: an argument-less `useEffect(() => { onCloseRef.current = onClose; })` instead of assigning inline.
- **No `setState` directly inside an effect body** (`react-hooks/set-state-in-effect`) — `Dashboard.tsx` has one pre-existing, intentionally-unfixed violation (`useEffect(() => { if (window.matchMedia(...).matches) setSongsVisible(false); }, [])`, a one-time initial-layout check); don't treat its presence as license to add more, `npm run lint`'s `✖ N problems (1 error, ...)` baseline expects exactly this one.

## GitHub Pages `basePath` gotcha

Production is served under `/Komadi/...` (`basePath` in `next.config.ts`, only set when `GITHUB_PAGES=true`), but `npm run dev` has an empty `basePath`. Any **root-absolute** hardcoded asset path (`/images/eras/60s.jpg`, `/icons/foo.svg`, …) therefore 404s in production while working perfectly in dev — this already broke the era-card images once. Prefix such paths with `process.env.NEXT_PUBLIC_BASE_PATH` (see `ERA_IMAGES` in `src/lib/constants.ts`, or `RegisterServiceWorker.tsx` for the same pattern applied to `sw.js`). Metadata-API paths (`icons: {...}` in `layout.tsx`) are fine as-is as long as they're written *without* a leading slash — Next resolves those against `basePath` automatically. Before trusting a new hardcoded static path, verify it survives a real production build: `GITHUB_PAGES=true npm run build` and grep `out/` (or the built JS chunks) for the path.
