## Commands

- `npm run dev` — dev server on **https://localhost:3000** (HTTPS, not HTTP — required because the backup feature uses the File System Access API / Web Share API, which need a secure context). Uses a self-signed cert auto-generated into `certificates/` on first run.
- `npm run build` — production build; static export to `out/` (`output: "export"` in `next.config.ts`).
- `npm run lint` — ESLint (flat config, `eslint.config.mjs`).
- `npm run backup` — exports the `songs` table to `backups/songs-<timestamp>.json` via the Supabase REST API (`scripts/backup-songs.mjs`).
- `node --env-file=.env.local scripts/fill-chords-text.mjs [--id <song_id>] [--dry]` — fills `songs.chords_text` (UG markup for "Akordi v aplikaciji") from `chords_source_url`; adds a `Capo: N` line on top when UG has a capo the description doesn’t mention; without `--id` it does every song with a UG link and empty `chords_text`, in batches of 20 with 60 s pauses.
- `node --env-file=.env.local scripts/fill-youtube-embed-ids.mjs [--id <song_id>] [--dry]` — fills `songs.youtube_embed_ids` (fallback YouTube videos for the chords viewer's mini player) from a YouTube search scrape; same batching, plus 1 s between songs and up to 3 retries (5/15/30 s) because after a few hundred searches YouTube intermittently drops connections (`UND_ERR_CONNECT_TIMEOUT`) — re-running only processes songs still missing the column, so a rerun picks up failures. Both are run per new song by the `dodaj-iz-cakalne-vrste` skill (step 7b).
- Testing on a phone: open `https://<ip-with-dashes>.sslip.io:3000` (e.g. `10-29-66-105.sslip.io`), **not** the bare IP — YouTube refuses every embed (error 150) on a bare-IP origin, so the mini player only works via a hostname. `*.sslip.io` is in `allowedDevOrigins` (`next.config.ts`); a bare new IP must be added there too, or Next blocks the dev JS and the page loads without songs. On the user's desktop (DESKTOP-UIK53J5) Ethernet has a **static IP 192.168.1.200** (set 2026-10-01, gateway/DNS 192.168.1.1), so the phone bookmark is always `https://192-168-1-200.sslip.io:3000`, and the Task Scheduler task **"Komadi dev server"** starts `npm run dev` hidden at logon (`%LOCALAPPDATA%Komadidev-server.ps1`, skips if port 3000 already listens; log `dev-server.log` there) — so a manual `npm run dev` there fails with the port in use; stop the background one first (`Stop-ScheduledTask "Komadi dev server"` doesn't kill the node child — end the `node.exe` listening on 3000).
- No test suite exists in this repo.

Supabase Edge Functions are deployed separately from the Next.js build, via the Supabase CLI, not `npm run build`:

```powershell
supabase functions deploy guess-era
supabase functions deploy similar-songs
```

Both read one shared secret (`supabase secrets set ANTHROPIC_API_KEY=sk-ant-...`). Full one-time setup (CLI install/login/link, secret, deploy, smoke test) is documented step-by-step in README.md under "AI predlog obdobja".

## Architecture

**Fully static, client-only app — no custom server.** `next.config.ts` sets `output: "export"` (deployed to GitHub Pages by `.github/workflows/deploy.yml`, `basePath` driven by the `REPO_NAME` constant at the top of that file). The whole app is one client-component tree from `src/app/page.tsx` → `AuthGate.tsx` → `Dashboard.tsx`. There are no Next.js API routes; the only server-side code is the two Supabase Edge Functions under `supabase/functions/`, which are their own deploy target.

**Prijava (login is mandatory) — same Supabase Auth as the TomsStudios hub.** `src/app/page.tsx` renders `AuthGate.tsx`, which checks `getSession()` (8 s fallback to the login screen), takes over a `#sb_at=…&sb_rt=…` hash from the hub via `setSession()` and strips it, and renders `LoginScreen.tsx` (login/register with first/last name into `user_metadata`, invite-only via the hub's `allowed_emails` trigger, forgot password + `PASSWORD_RECOVERY` new-password form) or `<Dashboard key={user.id} user={user} />`. On `zig4to.github.io` the session is shared with the hub through localStorage, so `supabaseClient.ts` must **not** set a custom `storageKey`. `UserAvatar.tsx` (default export `UserMenuSection`) is the collapsible "Uporabnik" section at the top of the ⋮ menu (`SettingsMenu` `user` prop, above "Nastavitve"): initials, name/email, a name form if missing, and "Odjava". Each user has their own library; existing data belongs to ziga.skater@gmail.com. **Trap: `select` on `songs` is open to every authenticated user** (needed by "Skupno"), so any query for the user's own songs must add `.eq("user_id", user.id)` and the realtime subscription on `songs` carries `filter: user_id=eq.<id>`; all other tables are filtered by RLS alone. **"Skupno"** (icon-only sky button in the header right of the "+" add button, `komadi:shared:open`, Android-Back-aware) swaps the "Vsi Komadi" list to other users' songs (`.neq("user_id")`, loaded on each open, deduped by normalized title+author via `dedupeShared`/`songMatchKey` in `src/lib/importShared.ts`); the same filters apply, home highlights are hidden, and `SongCard` gets `onImport`/`inLibrary` — its menu then shows only "Uvozi v mojo knjižnico" (no edit/playlist/report; no `onChordsClick`, so foreign `copy_count` is never bumped). `importSharedSongs` copies content columns (chords, links, `chords_text`, `youtube_embed_ids`, `lrc_offsets`) but not personal ones (favorite, Jam, goal, copy_count, batch) and sets `songs.imported_from`. Node scripts and the `dodaj-iz-cakalne-vrste` skill use `SUPABASE_SERVICE_ROLE_KEY` from `.env.local` (bypasses RLS; must set `user_id` explicitly). Jam is per-user for now.

**"Pregled in odobritev" — songs added by the `dodaj-iz-cakalne-vrste` skill wait for approval.** The skill inserts with `songs.review_pending = true` (`0030_add_review_pending.sql`). `Dashboard.tsx` keeps every own row in `allSongs` (the state behind `setSongs`) and derives `songs` (the library — every other view, list, Novo, Popularno, Jam pickers …) without pending ones, and `reviewSongs` (oldest first). Use `allSongs` for rollbacks and id lookups that must also cover pending songs (e.g. `handleDelete`, the chords viewer). "Skupno" loads only `review_pending = false`. The full page (`reviewOpen`, `usePersistentBool`, mutually exclusive with the other full pages, Android-Back-aware) is opened from the ⋮ menu item between "Čakalna vrsta" and "Popravi skladbe" (teal count badge): each song as a teal-framed `SongCard` (Uredi/Izbriši in its menu, inline `SongForm`, chords viewer works); the teal header (status "✓ akordi, ✓ predvajalnik" / "pripravljena", date, chevron) toggles `reviewExpanded` — the rows below the card (genre/era/mood/origin, "Uredi besedilo", "Odobri" and the two verify buttons) are collapsed by default — and "Odobri" (`handleApprove`, sets `review_pending = false`; enabled only once both "Akordi preverjeni" and "Predvajalnik preverjen" are set — see "Preverjene skladbe" below), plus "Odobri vse preverjene (n/m)". Songs can also be sent back to review by setting `review_pending = true` (done via the Supabase MCP for the 10 oldest songs and Ti si mi u krvi / Water Witch / Happy Xmas on 2026-10-01); while pending they are hidden from every library view, incl. Priljubljeno and Mojih 20, and every song in review gets "Sam Špili".

**All state lives in `Dashboard.tsx`.** It owns `songs`, `filters`, `activeView` (`"list" | "newest" | "popular"`), and all form/modal state, passed down as props to `SongCard`, `SongForm`, `Filters`, `SettingsMenu`. There is no global store (no Context/Redux/Zustand) — everything is prop-drilled from this one component.

**AI calls always go through a Supabase Edge Function, never straight from the browser to Anthropic.** `guess-era` (suggest a decade from title+author) and `similar-songs` (find similar songs via Claude + web search) are invoked with `supabase.functions.invoke(name, { body })` and read `ANTHROPIC_API_KEY` from `Deno.env` server-side. This is what keeps the key out of the client bundle — necessary because the app is a static export with no backend to otherwise hide it behind. Both functions share the same secret.

**Cross-component UI state (open/closed panels, theme) syncs via localStorage + a custom `window` event, not lifted React state.** See `usePersistentBool` in `src/lib/usePersistentBool.ts` and `useTheme` in `src/lib/useTheme.ts`: each reads/writes one `localStorage` key and dispatches/listens for a custom event (`komadi-storage`, `komadi-theme`) so independent component instances (or a single component across a page refresh) stay in sync without sharing a parent. `useTheme` also holds the **app background** (⋮ → Nastavitve → Tema, a collapsible section: Sistemska/Svetla/Temna + "Ozadje" swatches = the same `BACKGROUNDS`/`BACKGROUND_ORDER` as the chords viewer / Sam Špili, shared in `src/lib/backgrounds.ts`, plus "Osnovna"; `komadi:appBg` = index, applied as `document.body.style.backgroundColor`). Default (no `komadi:appBg`) is **Antracit** while the theme is dark, the theme’s own background while light; "Osnovna" stores `none` (the theme’s own background). Picking a background also sets the theme (light swatch → light, else dark) and picking a theme removes the key (back to that default), so text never ends up light on a light background. `Filters.tsx` exports two separate components, `FiltersToggle` (the pill button, rendered inline with the "Novo"/"Popularno" buttons in `Dashboard.tsx`) and `Filters` (the panel, rendered separately below) that share state this way, and `Dashboard.tsx`'s `jamOpen` uses the same hook so refreshing the page mid-jam-session doesn't bounce back to the home screen. The `Filters` panel only closes via the `Filtri` toggle button or its own "Počisti filtre" button (always visible at the top of the panel, not gated on `hasActiveFilters`) — there is deliberately no click-outside-closes handler, so opening it and clicking elsewhere on the page (e.g. a genre chip inside it) doesn't unexpectedly dismiss it.

**Data model:** the core table is `songs` (`supabase/schema.sql` + `supabase/migrations/`, applied by hand — there's no migration runner; since 2026-10-01 the **Supabase MCP server** is connected in Claude Code (local scope, `project_ref=abjnxhfxjolwwxlckkje`), so Claude can apply a migration with `apply_migration` and inspect data with `execute_sql` instead of the user pasting SQL into the SQL Editor; still keep every schema change as a numbered file in `supabase/migrations/`; `0035_add_verification.sql` was applied this way). `genre` and `era` are fixed enums (`GENRES`, `ERAS` in `src/lib/constants.ts`, typed as unions in `src/types/song.ts`); `mood` and `origin` are free-text and user-extensible — `DEFAULT_MOODS`/`DEFAULT_ORIGINS` are only seed suggestion lists, not constraints, and `SongForm` lets the user type a new value that then shows up in future pickers/filters. `copy_count` drives the "Popularno" sort (see below). Up to four chord sources per song: `chords_url` (own-hosted PDF), `chords_source_url` (Ultimate Guitar link), `other_chords_url` (any other chords site, e.g. pesmarica.rs, for songs with no chords on UG/zabrenkaj.si — `0022_add_other_chords_url.sql`; the dropdown row is labelled with the link's hostname minus `www.` and a violet open-book icon), and `zabrenkaj_url` (link to the song's page on zabrenkaj.si, a Slovenian chords site — `0016_add_zabrenkaj_url.sql`; only the link is stored, never the page content). `zabrenkaj_url` was bulk-filled once for the ~94 library songs that exist there, by matching titles against `https://www.zabrenkaj.si/vse-pesmi/` and confirming the artist from each candidate page's `<title>` (`Izvajalec - Naslov - Akordi …`); new songs get it via the `dodaj-iz-cakalne-vrste` skill (step 4b) or by hand in `SongForm`. A second table, `author_images` (`author` text PK, `image_url`), holds one optional photo per author, settable from the small camera-icon button on any `SongCard` (`onSetAuthorImage`) and read into `authorImages` state in `Dashboard.tsx` for use as background art on cards/highlights. `songs.favorited_at` (`0023_add_favorited_at.sql`) records when a song was marked favorite (set by the SongCard menu toggle and SongForm, cleared on unfavorite) — the home screen's "Priljubljeno <mesec>" row (e.g. "Priljubljeno septembra", month in genitive, above "Obdobja", compact one-line cards in a horizontal swipe — phone: columns of 2 (`COLUMN_SIZE`); desktop: 3 × 3 pages filled row by row; newest favorite first) shows the current calendar month's favorites — when the user has none this month it shows other users' favorites of this month instead, one column per person (initials + name, the column's list scrolls vertically, columns swipe sideways; `OthersColumns`), and when they do have some, a "Drugi" pill ("Priljubljeno drugih" on desktop, `komadi:favorites:others`) toggles to that view; `othersFavorites` (approved, `.neq("user_id")`) and names come from `Dashboard.tsx` on mount — names via the `song_owner_names()` security-definer RPC (`0036_add_song_owner_names.sql`: id + first/last name of song owners only, no e-mail, `authenticated` only), since `auth.users` isn't readable from the browser; foreign cards get no Jam button and don't bump `copy_count`, and the viewer lookup includes them — and the full-page "Arhiv priljubljenih" (⋮ menu, `favArchiveOpen`, mutually exclusive with Jam/Goal/Popravi/Čakalna vrsta, Android-Back-aware) groups older months — nothing is moved at month change, it is derived from the date (`src/components/FavoritesMonth.tsx`). **Trap: the month comes from the device's local time zone**, so two devices can disagree around midnight on the last day of a month — the user's desktop was set to Russian Standard Time (UTC+3) and showed an empty "Priljubljeno oktobra" an hour before the phone did; that is a system setting, not a bug. Right below it, **"Preverjeno špila"** (`VerifiedSongs` in the same file) is the same for every user: own songs with `verified_player_at` (live from `songs`) plus other users’ verified, approved songs (`verifiedAll`, loaded once on mount — `select` on `songs` is open to all signed-in users; deduped by `songMatchKey`/`dedupeShared`, own copy wins; the viewer lookup includes them; foreign cards get no private-Jam button and don’t bump `copy_count`), last verified first, in the same layout (`FavoriteCard variant="verified"`: verification date, orange check instead of the star), with an empty-state hint when there are none. `queued_songs` (`title`, `author` only), `import_batches` (one row per run of the `dodaj-iz-cakalne-vrste` skill, `report` jsonb shaped like `ImportReport` in `src/types/song.ts`; songs point to it via `songs.import_batch_id`, `0021_add_import_batches.sql` — shown on the "Čakalna vrsta" page in the "Poročila" and "Zgodovina dodajanja" tabs, `src/components/ImportTabs.tsx`), `song_reports` (`song_id` FK with `on delete cascade`, a `title`/`author` snapshot, optional `note` — written by "Prijavi napako" in the `SongCard` hamburger menu, which opens a small inline form at the bottom of the card; `0018_add_song_reports.sql`. `Dashboard.tsx` owns the `reports` state; while a song has any open report it is hidden from the "Vsi Komadi" list only (`reportedSongIds`, filtered in `displaySongs`) and shown instead on the full-page "Popravi skladbe" view (`fixOpen`, a `usePersistentBool` alongside `jamOpen`/`goalOpen`, mutually exclusive with them): each song as a `SongCard` plus its report notes, a pencil button right of each note to edit it inline (needs the update policy from `0019_song_reports_update.sql`), "Uredi" (inline `SongForm`) and "✓ Popravljeno" (deletes all of its reports, which returns it to the list). `SettingsMenu.tsx` keeps a read-only quick-overview dropdown of the same reports (tap to expand the note; no ✓ there — resolving is only on the full page), passed in as props, plus a button that opens the full page), `goal_extras`/`jam_extras` (see below), and `playlists` + `playlist_songs` (`0025_add_playlists.sql`; `playlist_songs` is a join table with `on delete cascade` on both FKs and `unique (playlist_id, song_id)` — see "Playliste" below) round out the schema. `songs.chords_text` (`0026`) and `songs.youtube_embed_ids` (`0027`, `text[]`) feed the in-app chords viewer and its mini player (see below); both are omitted from `NewSong`. Every table except `author_images` has a `user_id` (`0029_add_user_accounts.sql`, default `auth.uid()`, so browser inserts need no code for it) and "own rows" RLS for `authenticated` — see "Prijava" below.

**Trap: "Pred 1960" and "1960s" render as the same home-screen label.** `formatEraLabel` in `src/components/HomeHighlights.tsx` maps both era values to "60's" (it strips the "19" prefix from any `<NN>s` value, and special-cases "Pred 1960" to the same string). Since the "Obdobja" row on the home screen only shows one card per era that actually has ≥1 song, assigning a `<1960` song to whichever of the two values doesn't already have songs creates a second, visually-identical "60's" card. Rule (user decision, 2026-09-25): every song from the 1960s or earlier gets `"Pred 1960"` (shown as "60's"); never write `"1960s"` (it is not in `ERAS`, and there is no DB-level enum to stop it). This already happened twice (CCR import, and two stray `"1960s"` songs) and was fixed by moving all such songs to `"Pred 1960"`.

**Trap: React portals break the "click outside Novo/Popularno closes the view" listener unless marked.** `Dashboard.tsx` has a `document`-level `pointerdown` listener (active only when `activeView !== "list"`) that resets `activeView` to `"list"` on any click outside `[data-view-toggle]`/`[data-view-section]` — but content rendered via `createPortal` (the merged `ChordsButtons` dropdown, its `PdfViewer` overlay, `SongCard`'s action-menu dropdown) is appended to `document.body`, physically outside `[data-view-section]`, even though it's logically part of it. Without an exception, clicking e.g. "Ultimate Guitar" (formerly "UG Tabs") inside that dropdown while on the Popularno tab got treated as an outside click and silently bounced the view back to "Vsi Komadi" before the link even opened. Fix/pattern: any portaled element that should count as "inside" the current view carries `data-view-portal`, and the listener's exclusion check includes `target.closest("[data-view-portal]")` alongside the other two. Any new `createPortal` content reachable from inside a Novo/Popularno/list row must carry this attribute too, or it will silently re-trigger this bug.

**"Popularno" popularity is driven by chord-button clicks, not song-title clicks.** Earlier versions copied the title to the clipboard on any click anywhere on a card and counted *that* towards `copy_count` — this was removed. Now `copy_count` only increments when the "Ultimate Guitar", "Zabrenkaj.si" or "PDF akordi" button is clicked (`handleChordsClick` in `Dashboard.tsx`, threaded down as `onChordsClick` through `SongCard`, `ChordsButtons`, and `FeaturedArtists`/`SongRow`). Cards no longer copy anything to the clipboard at all.

**The song list renders in pages of `RESULTS_PAGE` (40).** `Dashboard.tsx` renders only `displaySongs.slice(0, visibleResults)` and a `LoadMoreSentinel` (IntersectionObserver, 600 px margin, keyed by the count so each page re-observes) adds the next 40 near the bottom; the count resets whenever `filters` change (derived from a `{ key: JSON.stringify(filters), count }` state, no effect). Without it the first one or two typed letters matched ~all songs and re-rendered ~290 `SongCard`s per keystroke, so typing/deleting those letters lagged — and deleting the last letter re-rendered the whole unfiltered list, so the unfiltered "Vsi Komadi" list is paged too. Exception: `handleBackFromFilter` sets the count to `Infinity` for the empty-filter key, because it restores `homeScrollY`, which can be deep in the list. On phones the search field grows to fill the row while focused or non-empty (`searchWide`), Jam/Playliste shrink to icons, and Enter blurs the field to close the keyboard.

**"Vsi Komadi"'s header button swaps meaning depending on whether a filter is active.** With no active filter the heading row itself is the collapse toggle — the title and the empty space right of it up to a chevron on the right edge (same look as the collapsible Obdobja/Žanri/Avtorji/Predstavljeno headings, `HomeSectionHeading.tsx`, `komadi:home:<key>`) (`songsVisible`, persisted as `komadi:songs:visible` in localStorage once the user toggles it; until then it defaults to collapsed on desktop via a one-time mount effect — see the ESLint gotcha below for why that effect is a known, intentional lint exception). The moment any filter is active (`hasActiveFilters(filters)` or `authorFilter`), the same slot renders "← Nazaj" instead, which calls `handleBackFromFilter` (clears filters, closes the `Filters` panel, restores scroll position) — the two buttons never show at once.

**"Naključno"/"Delno naključno" share one `randomPick` slot, with a flag for how it was picked.** `pickRandom()` (plain "Naključno") and `handlePartialConfirm()` (after picking a dimension+value in "Delno naključno") both set the same `randomPick` state, but only the latter sets `randomPickFromPartial = true`. This matters for the "↻ Izberi drugo" button: `handlePickAnother()` branches on that flag — for a plain pick it just calls `pickRandom()` again, but for a partial pick it clears `randomPick` and re-opens the "Delno naključno" selection form (`handlePartialStart()`, which also re-rolls which dimension — genre/author/era/mood/origin — is asked for) rather than silently picking a new song from the whole library. The "↻ 5" button (`pickRandomFive`) is independent of this flag — it always samples from the currently filtered pool and renders a `SongCard` grid underneath, closed by `setRandomFive(null)` whenever a new pick/partial-pick happens. Author matching in "Delno naključno" is soft (`s.author.toLowerCase().includes(word)` per word in the query, any order) rather than an exact match, so a partial or reordered name still finds the artist.

**"Jam" is a live, shared queue for a band practice session, synced via Supabase Realtime.** Two columns on `songs` (`jam_added_at`, `jam_played`) turn any existing song into a queue entry — `jam_added_at` doubles as the queue order and "is currently in the jam" flag; a separate table, `jam_extras` (title/author/played only, no genre/era/etc.), covers songs suggested during a jam that aren't in the library yet ("Skladbe ni" quick-add). `Dashboard.tsx` merges both into one `jamItems` list (see the `JamItem` discriminated union) and always shows a "Trenutna skladba"/"Naslednja skladba" label on the first two unplayed entries. Because a jam session has multiple people adding/checking off songs from their own phones at once, `Dashboard.tsx` subscribes to Supabase Realtime (`supabase.channel("songs-and-extras").on("postgres_changes", ...)`) for `songs`, `jam_extras`, and `goal_extras` (see below) and merges every INSERT/UPDATE/DELETE straight into local state — this requires the tables to be added to the `supabase_realtime` publication (`supabase/migrations/0013_enable_realtime.sql`, `0015_add_goal_list.sql`), which is *not* covered by RLS policies and must be run once by hand like every other migration in this repo. There is no origin-filtering/de-duplication of a client's own optimistic update against its own echoed realtime event — the echo just re-applies the same value, which is harmless.

**Trap: realtime UPDATE payloads omit unchanged large (TOAST) columns — always merge, never replace.** Postgres logical replication doesn't send unchanged TOASTed values, so after e.g. a `copy_count` bump the `songs` UPDATE event's `payload.new` has no `chords_text`. The handler in `Dashboard.tsx` therefore does `{ ...s, ...song }`; replacing the object outright made the song lose `chords_text`, which unmounted the chords viewer ~0.5 s after opening it (clicking "Akordi v aplikaciji" is itself what bumps `copy_count`). Apply the same merge to any new realtime handler on a table with long text/array columns.

**"Akordi v aplikaciji" — in-app chords viewer (UG Tabs style), an extra option alongside the UG/Zabrenkaj/PDF links, not a replacement.** `ChordsButtons`' merged dropdown shows it as the first row only when `song.chords_text` is set; it opens `ChordsViewer.tsx` (full-screen portal, `data-view-portal`, `useBackableOpen`). The open song id lives in localStorage (`komadi:chords:open`, `src/lib/openChords.ts`: `openChordsViewer`/`closeChordsViewer`/`useOpenChordsSongId`, synced via the `komadi-storage` event) so a page refresh reopens it on phone and desktop; `ChordsButtons` only sets it, and the viewer is rendered in exactly one place — at the end of `Dashboard.tsx`'s JSX, for `songs.find(id)` — so a song shown on several cards never opens two viewers. `src/lib/chords.ts` parses the UG markup (`[ch]Am[/ch]`, `[tab]…[/tab]` ignored, `[Verse]` section lines): a chord line directly above a lyric line becomes a `pair` of chunks (chord + the lyric slice up to the next chord), rendered as flex-wrap inline blocks so the chord stays over its syllable when transposing lengthens the name or the line wraps on a phone — don't go back to two monospace `<div>` rows aligned by column. Guitar tabs are the opposite: consecutive string lines (`e|--5--|`, `Eb|…`, also `[ch]G[/ch]|---` where UG mis-tagged the string name) are grouped *before* pairing into a `tab` line (`isTabStaff`), with the chord line directly above (`[ch]` or plain chord names) attached as its transposed header; they render `whitespace-pre` with no wrapping inside an `overflow-x-auto` block, so wide tabs scroll sideways at the normal font size instead of breaking the strings apart. In the song body the string lines are hidden by default — the chord header then shows as a plain wrapping sequence, each chord a fixed `max(4, len+1)ch` cell (`F#  Bm  F#  Bm`), not at its tab columns and without the sideways scroll — a "Tab" pill right of the section heading (`[Solo]` etc.) reveals that section's tabs; tabs before the first section share one pill. Beat-count lines above a tab (`1 + 2 + 3 +`) are part of it, a short plain-text title right above one ("Solo", "Picking") becomes a `section` with `tabLabel` (doesn't end the description by itself), `H` counts as a string name (Slovene B), and tabs inside "Opis skladbe" are always shown. **"Pametni predvajalnik" / "Smart play" — the song follows the singing.** An icon-only button left of ▶ (shown only when the song has synced lyrics) starts playback and turns following on; clicking it again turns following off without stopping the music; plain ▶ only plays, as before, and keeps the autoscroll control (hidden while following is on). `src/lib/syncedLyrics.ts` fetches line-timed lyrics from LRCLIB (`lrclib.net/api/search`, CORS-open, no key; up to 8 synced versions cached per song in `komadi:chords:lrc:<id>` as `{ query, candidates }` where `query` is a version tag + title + author — empty results are cached too, and a changed title/author (e.g. a fixed typo) refetches; `CCR` is aliased to the full name). `parseLrc` keeps empty LRC lines (they mark where an instrumental gap starts, i.e. the end of the previous line). `pickCandidate` takes the version whose length is closest to the playing YouTube video. `alignLyrics` maps LRC lines to body lines: words normalized (no diacritics/punctuation, hyphen/apostrophe joins, 1-letter words dropped, `gelatin`≈`gelatine`), score = max(Dice, 0.9·share of LRC words contained), minimum 0.4. **Rule (user decision, 2026-09-30): forward only — a sung line is never repeated and the mark never jumps back.** The assignment is chosen for the whole song at once (dynamic programming: maximum total score under a monotone order, `ALIGN_SKIP` 0.02 per skipped tab line), not greedily line by line. The greedy version failed both ways: a line written several times in a row ("Where is my mind?" ×3) stuck on the first copy because distance 0 always beat the next one, and an intro shout or a chorus sung here but written only further down pulled the mark far ahead and lost a whole verse ("Come on Eileen", "99 Problems"). Staying on the same tab line is allowed only for an LRC line that matches that line's words *not used* by the previous LRC line on it (several short LRC lines inside one long chord line — "Killer Queen, gunpowder, gelatine"); an identical line therefore always moves to the next one. A sung line the tab doesn't have at that spot (chorus written once) stays unmatched — the mark waits; this is why tabs must contain every sung line as often as it is sung. When one LRC line spans several chord-sheet lines ("You'd better run, better run, outrun my gun" = two lines in Pumped Up Kicks), following lines whose words are ≥80 % in the rest of the LRC line are consumed too (extra point at a proportional time), up to the line the next matched LRC line owns. A tab line split between this LRC line and the next one (LRC "Except the little fish, bumped into me" + "I swear he was trying to talk to me" vs tab "Except the little fish" / "Bumped into me, I swear he was" / "Tryin' to talk to me" in Where Is My Mind?) is consumed too when ≥80 % of its words are in the rest of this LRC line plus the next one (at least one in this one) — otherwise no LRC line owns it and it stays unmarked. Likewise backwards: up to 2 unmarked tab lines right before the matched one whose words are ≥80 % in the start of the LRC line get the LRC start time and the matched line moves to its word-proportional time (LRC "War is over, if you want it" matched "If you want it" and left "War is over" unmarked in Happy Xmas). Split times inside one LRC line use at most `WORD_SEC_MAX` = 1.2 s per word, so a long pause before the next LRC line doesn’t push the last part ("Now") seconds late. Checked on 46 library songs: only additions (1484 → 1506 highlighted lines), nothing lost. LRC lines made of one repeated word ("Run, run, run", "la la la") only match at ≥0.8. Checked on 60 library songs against the old greedy version: highlighted tab lines 1033 → 1133, no backward jumps. Frozen (verified) songs are unaffected. **Android hardware Back closes the current in-app view instead of exiting the PWA.** The manifest runs `"display": "fullscreen"` (since 2026-10-01, was `standalone`: the installed app has no status/nav bar, so `requestFullscreen` — and the browser’s "swipe from top to exit" toast — is skipped there: `isAppFullscreen()`/`canBrowserFullscreen()` in `src/lib/openChords.ts`, the Sam Špili landscape lock still runs; `globals.css` pads `body` by `env(safe-area-inset-*)` under `(display-mode: fullscreen)`; to revert, `git revert` that commit and reinstall the app), and the app is a single client-rendered page with no router — it never pushed browser history entries, so on Android the system Back gesture used to close the installed PWA outright rather than backing out of whatever filter/modal/panel was open. `src/lib/backNavigation.ts` (a module-level LIFO stack + one shared `popstate` listener) and `src/lib/useBackableOpen.ts` (the hook components call) fix this: any component with an existing `isOpen` boolean and an existing close function — the era/genre/author filter view, the Novo/Popularno tabs, the add/edit `SongForm`, `PdfViewer`, the `Filters` panel, `SettingsMenu` — calls `useBackableOpen(isOpen, onClose)` once, and Back then closes just the most-recently-opened one, in order, exactly as if its own close button/outside-click had been used. It never duplicates the existing close logic, only calls it. Closing one view and opening another in the same render (e.g. a ⋮ menu item that closes the menu and opens "Popravi skladbe"/"Mojih 20 skladb") used to race the async `history.back()` against the new `pushState` and make Back exit the PWA; `backNavigation.ts` now defers pushes (`pendingPushes`) until its own pending backs have fired. Every new full-page view must call `useBackableOpen` so Back returns to the home screen. Known limitation: closing a non-full-screen panel out of LIFO order (via its own button while something opened *after* it is still open) can desync the stack by one entry — self-corrects after one extra Back press; not reachable for `PdfViewer` since it's always full-screen and therefore always topmost.

## Windows/Turbopack dev quirks

- Tailwind v4's important modifier is a **trailing** `!` (`mt-3!`) — a leading `!mt-3` (the v3 syntax) is silently ignored, not an error.
- The dev server sometimes doesn't pick up new Tailwind arbitrary-value/important classes via HMR. If a style change doesn't appear, kill the dev server and re-run `npm run dev` before assuming the class is wrong.
- Turbopack's CSS worker has been observed to crash on Windows (exit code `0xc0000142`) after repeated hot-reloads. If `next dev` starts returning 500s on every request, stop it, `rm -rf .next`, and restart.
- After `git pull` adds a new dependency to `package.json`, `node_modules` doesn't update itself — `npm run dev` will start fine but the feature using that dependency fails at runtime (e.g. `PdfViewer.tsx` throwing "Cannot find module 'pdfjs-dist'" the first time it renders). Run `npm install` after any pull that touches `package.json`/`package-lock.json`, then restart the dev server.

## ESLint react-hooks gotchas

`eslint-plugin-react-hooks` here enforces two rules that are easy to trip
when writing a new custom hook:
- **No ref writes during render** (`react-hooks/refs`) — `someRef.current = x` must happen inside a `useEffect`, never directly in the component/hook body. See `src/lib/useBackableOpen.ts` for the fix: an argument-less `useEffect(() => { onCloseRef.current = onClose; })` instead of assigning inline.
- **No `setState` directly inside an effect body** (`react-hooks/set-state-in-effect`) — `Dashboard.tsx` has one pre-existing, intentionally-unfixed violation (`useEffect(() => { if (window.matchMedia(...).matches) setDefaultSongsVisible(false); }, [])`, a one-time initial-layout check); don't treat its presence as license to add more, `npm run lint`'s `✖ N problems (1 error, ...)` baseline expects exactly this one.

## GitHub Pages `basePath` gotcha

Production is served under `/Komadi/...` (`basePath` in `next.config.ts`, only set when `GITHUB_PAGES=true`), but `npm run dev` has an empty `basePath`. Any **root-absolute** hardcoded asset path (`/images/eras/60s.jpg`, `/icons/foo.svg`, …) therefore 404s in production while working perfectly in dev — this already broke the era-card images once. Prefix such paths with `process.env.NEXT_PUBLIC_BASE_PATH` (see `ERA_IMAGES` in `src/lib/constants.ts`, or `RegisterServiceWorker.tsx` for the same pattern applied to `sw.js`). Metadata-API paths (`icons: {...}` in `layout.tsx`) are fine as-is as long as they're written *without* a leading slash — Next resolves those against `basePath` automatically. Before trusting a new hardcoded static path, verify it survives a real production build: `GITHUB_PAGES=true npm run build` and grep `out/` (or the built JS chunks) for the path.
